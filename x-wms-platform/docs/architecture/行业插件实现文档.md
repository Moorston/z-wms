# X WMS 行业插件实现文档

> 基于SPI+事件+策略+独立类加载器的插件化架构
> 三大行业插件：医药GSP / 食品冷链 / 电商大促

## 一、插件架构总览

### 1.1 5大扩展点

| 扩展点接口 | 拦截流程 | 方法数 |
|-----------|---------|--------|
| `InboundExtension` | ASN→收货→质检→上架 | 5个 |
| `OutboundExtension` | 订单→分配→波次→拣货→复核→发运 | 6个 |
| `InventoryExtension` | 扣减→预占→调拨→盘点→预警 | 5个 |
| `QualityExtension` | 质检触发→抽样→项目→结果 | 5个 |
| `OperationExtension` | 作业调度→PDA交互 | 预留 |

### 1.2 执行机制

```
核心业务流程 → PluginExtensionExecutor → 按优先级遍历行业插件
                                         ↓
                                    第一个拦截结果即返回（责任链）
                                         ↓
                                    全部pass则执行默认逻辑
```

### 1.3 配置方式（Nacos动态配置）

```yaml
wms:
  plugin:
    industry:
      enabled: true
      plugins:
        gsp:
          enabled: true
          priority: 200
        coldchain:
          enabled: true
          priority: 180
        ecommerce:
          enabled: false    # 非大促期间禁用，大促前开启
          priority: 150
```

## 二、医药GSP插件

### 2.1 业务场景

| 场景 | 管控点 | 实现方式 |
|------|--------|---------|
| 首营审核 | 新供应商/新品种入库前必须审核 | `beforeAsnCreate` 拦截 |
| 批号效期 | 医药商品批号+效期必填，唯一校验 | `beforeReceive` 拦截 |
| FEFO分配 | 近效期先出，覆盖默认FIFO | `modifyAllocation` 修正 |
| 温湿度监控 | 冷库2-8℃，每30分钟记录 | `GspTemperatureService` |
| 特殊药品 | 麻精毒放双人拣货/复核/盘点 | `beforePick/beforeReview/beforeStocktake` |
| 随货同行单 | 出库必须生成GSP随货同行单 | `beforeShip` 生成 |
| 质检 | 首营全检，常规AQL抽样 | `QualityExtension` |
| 效期预警 | 30/60/90天三级预警 | `onInventoryAlert` |

### 2.2 文件清单

| 文件 | 说明 |
|------|------|
| `GspInboundExtension.java` | 入库扩展（首营/批号/温区/养护） |
| `GspOutboundExtension.java` | 出库扩展（FEFO/双人复核/随货单） |
| `GspInventoryExtension.java` | 库存扩展（效期预警/特殊药品） |
| `GspQualityExtension.java` | 质检扩展（全检/AQL抽样） |
| `GspBatchService.java` | 批号效期管理服务 |
| `GspTemperatureService.java` | 温湿度监控服务 |

### 2.3 核心代码逻辑

**FEFO近效期先出**：
```java
// 按效期升序排序，优先分配近效期批次
inventoryList.sort((a, b) -> expireDateA.compareTo(expireDateB));
```

**温湿度标准**：
- 冷库：2-8℃，阴凉库：≤20℃，常温库：0-30℃
- 相对湿度：35%-75%
- 每30分钟自动记录，超标立即报警

## 三、食品冷链插件

### 3.1 业务场景

| 场景 | 管控点 | 实现方式 |
|------|--------|---------|
| 到货温度 | 冷链商品收货必须检测温度 | `beforeReceive` 拦截 |
| 温区校验 | 冷冻≤-18℃，冷藏0-4℃，恒温10-15℃ | `ColdChainTemperatureService` |
| 温区匹配 | 商品温区与库位温区必须匹配 | `suggestPutaway` 建议 |
| FEFO保质期 | 先到期先出 | `modifyAllocation` 修正 |
| 断链检测 | 温度超标持续5分钟视为断链 | `detectBrokenChain` |
| 装箱温度 | 复核时检测装箱温度 | `beforeReview` 拦截 |
| 运输温控 | 发运启动全程温度监控 | `beforeShip` 启动 |
| 跨温区调拨 | 冷冻→冷藏需品质评估 | `beforeTransfer` 拦截 |

### 3.2 文件清单

| 文件 | 说明 |
|------|------|
| `ColdChainInboundExtension.java` | 入库扩展（到货温度/温区） |
| `ColdChainOutboundExtension.java` | 出库扩展（FEFO/装箱温度/运输温控） |
| `ColdChainInventoryExtension.java` | 库存扩展（在库监控/跨温区调拨） |
| `ColdChainTemperatureService.java` | 冷链温度监控服务 |

### 3.3 温区标准

| 温区 | 温度范围 | 典型商品 |
|------|---------|---------|
| 冷冻 FROZEN | ≤-18℃ | 速冻食品、肉类 |
| 冷藏 CHILLED | 0-4℃ | 生鲜、乳制品、疫苗 |
| 恒温 CONSTANT | 10-15℃ | 巧克力、葡萄酒 |
| 常温 NORMAL | 15-25℃ | 普通食品 |

## 四、电商大促插件

### 4.1 业务场景

| 场景 | 管控点 | 实现方式 |
|------|--------|---------|
| 预售预占 | 预售订单锁定活动库存池 | `beforeOrderCreate` 预占 |
| 活动库存池 | 活动库存与日常库存隔离 | `EcommercePreSaleService` |
| 预占超时 | 30分钟未支付自动释放 | 定时任务扫描 |
| 大促波次 | 按快递+区域聚合，容量500 | `EcommerceWaveService` |
| 爆款识别 | 订单SKU频率Top10 | `identifyHotSkus` |
| 极速出库 | 单SKU+已预占→跳过复核 | `isFastShipMode` |
| 快递单批量 | 大促高并发批量获取 | Kafka+虚拟线程 |
| 售罄预警 | 已售70%/90%预警 | `onInventoryAlert` |

### 4.2 文件清单

| 文件 | 说明 |
|------|------|
| `EcommerceOutboundExtension.java` | 出库扩展（预售/大促波次/极速出库） |
| `EcommerceInventoryExtension.java` | 库存扩展（活动库存/售罄预警） |
| `EcommercePreSaleService.java` | 预售预占服务 |
| `EcommerceWaveService.java` | 大促波次优化服务 |

### 4.3 大促波次策略

```
订单 → 按快递分组 → 按区域分组 → 按容量(500)拆波次
                                         ↓
                              爆款SKU单独波次（批量拣货）
                                         ↓
                              极速出库模式（拣货即发运）
```

## 五、插件配置与注册

### 5.1 核心类

| 类 | 说明 |
|----|------|
| `IndustryPluginConfig` | Nacos动态配置，启用/禁用/优先级 |
| `PluginExtensionExecutor` | 扩展点执行器，责任链模式统一调用 |
| `WmsPlugin` | 插件基类接口 |
| `ExtensionResult` | 扩展点执行结果（pass/intercept/reject） |

### 5.2 使用示例

```java
// 核心业务中调用扩展点
ExtensionResult result = extensionExecutor.executeInbound("beforeReceive", context);
if (result.isRejected()) {
    throw new BizException(result.getMessage());
}
if (result.isIntercepted()) {
    // 使用插件返回的数据（如指定库区、指定批号）
    applyExtensionData(result.getData());
}
// 继续默认流程
```

## 六、扩展新行业插件

1. 实现对应扩展点接口（如 `InboundExtension`）
2. 添加 `@Component` 注解，Spring自动注册
3. 在Nacos配置中启用并设置优先级
4. 无需修改核心代码，热插拔生效

## 七、行业插件对比

| 维度 | 医药GSP | 食品冷链 | 电商大促 |
|------|---------|---------|---------|
| 核心痛点 | 合规监管 | 品质保障 | 效率峰值 |
| 优先级 | 200 | 180 | 150 |
| 库存策略 | FEFO效期 | FEFO保质期 | 活动库存池 |
| 温度管控 | 温湿度记录 | 全程冷链断链 | 无 |
| 出库特点 | 双人复核+随货单 | 装箱温度+运输温控 | 极速出库+批量快递 |
| 质检要求 | 强制全检/抽检 | 温度抽检 | 无 |
| 启用时机 | 始终启用 | 始终启用 | 大促期间启用 |
