# 行业插件深度深化分析

---

## 一、业务定义与目标

### 1.1 定义

行业插件（Industry Plugin）是X WMS基于插件化架构，为不同行业（医药GSP、食品冷链、电商大促等）提供的行业专属业务规则和流程扩展，在不修改核心代码的前提下，通过插件机制注入行业特性。

### 1.2 核心目标

| 目标 | 衡量指标 |
|------|---------|
| 行业适配 | 覆盖医药/冷链/电商三大行业 |
| 核心稳定 | 插件不影响核心系统 |
| 可扩展 | 新增行业只需开发插件 |
| 合规达标 | 行业合规率100% |

### 1.3 插件化架构

```
插件化架构
├── 核心系统（WMS Core）
│   ├── 标准业务流程
│   ├── 扩展点（Extension Point）
│   └── 插件管理器（Plugin Manager）
├── 行业插件
│   ├── 医药GSP插件（优先级200）
│   ├── 食品冷链插件（优先级180）
│   └── 电商大促插件（优先级150）
├── 插件机制
│   ├── SPI扩展点接口
│   ├── 插件注册/发现
│   ├── 插件优先级排序
│   ├── 插件条件匹配（按货主/仓库/商品）
│   └── 插件热加载（可选）
└── 扩展点清单
    ├── 入库质检扩展点
    ├── 上架规则扩展点
    ├── 出库分配扩展点
    ├── 波次执行扩展点
    ├── 库存扣减扩展点
    ├── 批次管理扩展点
    ├── 费收计费扩展点
    └── 报表扩展点
```

## 三、状态机设计

插件本身无状态机，插件可扩展核心状态机的流转条件和动作。例如GSP插件扩展入库质检状态机，增加首营审批状态。

## 四、核心业务场景详解

### 4.1 医药GSP插件

**GSP合规要求：**
- 首营品种/首营企业审批（首次经营的品种和企业需质量审批）
- 药品入库验收（双人验收、批号效期核对、外观检查）
- 药品养护（重点品种每月养护，一般品种每季，养护记录）
- 温湿度监控（冷库2-8℃，阴凉库≤20℃，常温库0-30℃，实时监控记录）
- 电子监管码（核注核销，扫码上传药监平台）
- 近效期催销（近效期药品预警、催销表）
- 不合格药品管理（不合格品台账、销毁记录、双人复核）
- 追溯管理（药品从入库到出库全批次追溯）
- 特殊药品（麻精药品双人双锁、专册登记）

**插件扩展点：**
- 入库质检：GSP验收流程+双人验收
- 上架规则：温区匹配+批号集中
- 出库分配：FEFO先效期先出+近效期优先
- 库存管理：养护任务+温湿度记录
- 批次管理：电子监管码关联
- 报表：GSP合规报表

### 4.2 食品冷链插件

**冷链合规要求：**
- 温度监控（冷藏0-4℃，冷冻-18℃以下，实时温度记录）
- 温度告警（超温告警、处置记录）
- 效期管理（生产日期/保质期/先进先出）
- 批次追溯（从原料到成品全链路）
- 冷链断链处理（温度异常隔离、评估、处置）
- 冷链设备验证（冷库/冷藏车/保温箱验证）
- 食品召回（问题批次快速召回）

**插件扩展点：**
- 入库：温度检测+冷链设备验证
- 上架：温区强制匹配
- 出库：FIFO+温度校验
- 库存：温度监控+超温告警
- 批次：温度记录关联批次

### 4.3 电商大促插件

**大促场景要求：**
- 预打包（热销商品提前打包，大促时直接贴面单发货）
- 波次优化（大促波次参数调整，更大波次、更优路径）
- 面单预取（提前获取快递面单，避免大促接口限流）
- 库存预占（大促前锁定库存，防止超卖）
- 紧急补货（大促期间高频补货）
- 弹性作业（临时人员/设备调度）
- 异常快速处理（大促期间异常快速通道）

**插件扩展点：**
- 波次算法：大促波次参数+预打包波次
- 出库：预打包流程+面单预取
- 库存：大促安全库存+紧急补货
- 消息：大促异常告警
- 报表：大促实时战报

## 五、库存变化分析

行业插件不改变库存五态模型，但可扩展库存状态流转条件：
- GSP插件：质检增加GSP验收状态，不合格品冻结
- 冷链插件：温度异常自动冻结库存
- 大促插件：预打包库存从可用→预打包状态

## 六、技术实现方案

### 6.1 插件核心接口

```java
// 插件接口
public interface WmsPlugin {
    String getPluginCode();
    String getPluginName();
    int getPriority();
    boolean match(PluginContext context); // 按货主/仓库/商品匹配
}

// 扩展点接口示例
public interface InboundQcExtension extends WmsPlugin {
    QcResult doQc(InboundOrder order, QcContext context);
}

// 插件管理器
public class PluginManager {
    public <T extends WmsPlugin> List<T> getPlugins(Class<T> extensionType, PluginContext context);
    public <T extends WmsPlugin> T getFirstPlugin(Class<T> extensionType, PluginContext context);
}
```

### 6.2 插件配置

插件通过Spring SPI自动注册，配置文件指定插件启用状态、匹配条件（货主编码/仓库编码/商品分类）、优先级。插件可动态启用/禁用。

### 6.3 插件执行

核心业务在扩展点调用PluginManager获取匹配插件，按优先级排序，依次执行。插件可返回拦截结果（修改业务数据/阻断流程）或放行（执行核心默认逻辑）。

## 八、常见业务问题与解决方案

| 问题 | 解决方案 |
|------|---------|
| 插件影响核心稳定 | 插件隔离+优先级+异常降级+核心兜底 |
| 多插件冲突 | 优先级排序+条件匹配+插件互斥配置 |
| 行业合规变更 | 插件独立迭代+版本管理+合规检查 |
| 插件性能影响 | 插件异步化+缓存+限流+核心路径轻量化 |
| 新行业适配成本高 | 插件SDK+扩展点文档+示例插件+快速开发 |
| GSP合规风险 | GSP插件+定期审计+记录存档+监管对接 |
