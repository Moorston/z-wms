# 基础数据管理深度深化分析

---

## 一、业务定义与目标

### 1.1 定义

基础数据管理（Master Data Management）是WMS的核心数据基础，提供商品档案、客户/货主档案、供应商档案、仓库/库区/库位、批次属性、快递商、承运商等主数据的管理，是所有业务流程的数据基础。

### 1.2 核心目标

| 目标 | 衡量指标 |
|------|---------|
| 数据准确 | 主数据准确率 >99% |
| 数据完整 | 必填字段完整率100% |
| 数据唯一 | 重复数据率=0 |
| 同步及时 | 主数据同步延迟 <1分钟 |

### 1.3 业务场景全景

```
基础数据管理
├── 商品档案（SKU/条码/规格/分类/属性/批次属性/图片）
├── 客户/货主档案（货主信息/合同/计费规则/配送区域）
├── 供应商档案（供应商信息/质量评分/合作商品）
├── 仓库/库区/库位（四级架构/属性/状态）
├── 批次属性管理（批次定义/批次属性/效期规则）
├── 快递商管理（快递商/服务类型/报价/面单模板）
├── 承运商管理（承运商/车辆/司机/线路）
├── 商品分类（多级分类/分类属性）
├── 单位管理（基本单位/包装单位/换算关系）
├── 区域管理（省市区/配送区域/运费模板）
├── 条码管理（商品条码/箱码/托盘码/库位码）
├── 主数据同步（ERP推送/API同步/手动导入）
└── 数据质量（校验/去重/完整性检查）
```

## 四、核心业务场景详解

### 4.1 商品档案

商品基本信息（SKU编码/名称/规格/型号/品牌/分类/单位）、条码信息（商品条码/箱码/多条码）、包装信息（长宽高/重量/箱规/托盘规）、业务属性（是否批次管理/是否效期管理/是否序列号/ABC分类/存储温区/混放规则）、图片、扩展属性。支持多货主商品（同一SKU不同货主独立管理）。

### 4.2 客户/货主档案

货主信息（编码/名称/联系人/地址/合同/计费规则）、配送区域（支持的配送区域/运费模板）、业务配置（上架规则/分配规则/波次规则/质检规则）、信用额度、结算方式。3PL模式下货主是核心，所有业务按货主隔离。

### 4.3 供应商档案

供应商信息（编码/名称/联系人/地址/资质）、合作商品、质量评分（来料合格率/不良率/交货及时率）、结算方式、合同管理。

### 4.4 批次属性管理

批次定义（是否启用批次/批次号规则/批次属性）、批次属性（生产日期/有效期/批号/供应商批次/质检状态/自定义属性）、效期规则（保质期/近效期阈值/催销期/禁售期）。批次属性在入库时录入，出库时按规则分配。

### 4.5 快递商管理

快递商信息（编码/名称/服务类型/接口配置）、报价规则（按重量/体积重/区域/首重续重）、面单模板、电子面单API配置、快递商优先级。

### 4.6 主数据同步

ERP推送商品/货主/供应商到WMS（API/Kafka），WMS内部多仓同步，支持手动导入导出。同步冲突处理（以ERP为准/WMS可扩展字段）。

### 4.7 数据质量

数据校验（必填/格式/唯一性/业务规则）、去重（按编码/条码/名称去重）、完整性检查、数据质量报表、数据治理流程。

## 五、库存变化分析

基础数据不直接改变库存，商品/货主/批次属性是库存的维度，主数据变更影响库存查询和分配规则。

## 六、技术实现方案

### 6.1 核心表设计

```sql
-- 商品 wms_product (sku/product_name/spec/model/brand/category_code/unit/barcode/box_barcode/length/width/height/weight/is_batch/is_expiry/abc_class/temperature_zone/status)
-- 商品多条码 wms_product_barcode (sku/barcode/barcode_type)
-- 货主 wms_owner (owner_code/owner_name/contact/phone/address/contract_no/billing_rule/status)
-- 供应商 wms_supplier (supplier_code/supplier_name/contact/phone/quality_score/status)
-- 批次属性 wms_batch_attribute (sku/batch_no/production_date/expiry_date/supplier_batch/qc_status/attributes_json)
-- 快递商 wms_express (express_code/express_name/service_type/api_config/rate_template/status)
-- 商品分类 wms_product_category (category_code/category_name/parent_code/sort)
-- 单位换算 wms_unit_convert (sku/from_unit/to_unit/convert_rate)
```

### 6.2 主数据同步

ERP通过API/Kafka推送主数据→WMS接收→校验→保存→发送同步事件→各服务消费更新本地缓存。商品变更时通知相关业务模块刷新缓存。

## 八、常见业务问题与解决方案

| 问题 | 解决方案 |
|------|---------|
| 商品数据不准 | ERP同步+数据校验+定期核对+主数据治理 |
| 多货主商品混乱 | 货主隔离+货主级商品+编码规则+关联关系 |
| 批次属性缺失 | 入库强制录入+条码自动识别+校验+预警 |
| 快递报价不准 | 对接快递API+报价模板+重量校验+对账 |
| 主数据同步延迟 | Kafka实时同步+事件驱动+缓存刷新+补偿 |
| 数据重复 | 唯一约束+去重工具+编码规则+人工审核 |
