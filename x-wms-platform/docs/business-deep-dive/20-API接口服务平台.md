# API接口服务平台深度深化分析

---

## 一、业务定义与目标

### 1.1 定义

API接口服务平台（API Gateway & API Platform）是WMS对外提供标准化API接口、对接外部系统（ERP/电商平台/快递商/TMS/WCS/MES/AI平台）的统一入口和管理平台，涵盖API网关、接口管理、鉴权、限流、监控、文档等。

### 1.2 核心目标

| 目标 | 衡量指标 |
|------|---------|
| 接口标准化 | RESTful标准+统一响应格式 |
| 高可用 | 接口可用性 >99.9% |
| 安全可控 | 鉴权覆盖率100%，限流防刷 |
| 可观测 | 接口监控覆盖率100% |
| 易对接 | 接口文档完整，对接周期短 |

### 1.3 业务场景全景

```
API接口服务平台
├── API网关（Spring Cloud Gateway）
│   ├── 路由转发
│   ├── 统一鉴权（JWT/API Key/签名）
│   ├── 限流降级（Resilience4j）
│   ├── 灰度发布
│   └── 日志/TraceId
├── 对外API
│   ├── ERP对接（商品/订单/库存/入库回传/出库回传）
│   ├── 电商平台对接（订单推送/发货回传/库存同步）
│   ├── 快递商对接（电子面单/物流轨迹/运费查询）
```

## 二、业务流程图

### 2.1 API请求处理流程

```mermaid
flowchart TD
    A[外部系统请求] --> B[API网关]
    B --> C[鉴权校验]

    F -->{通过?}

    I -->{超限?}
    J -->|是| K[返回429]

    L --> M[业务服务处理]

    N --> O[记录调用日志]
    O --> P[返回结果]
```

## 四、核心业务场景详解

### 4.1 ERP对接

商品/货主/供应商主数据推送（ERP→WMS）、采购订单/ASN推送（ERP→WMS）、入库结果回传（WMS→ERP）、销售订单推送（ERP→WMS）、发货结果回传（WMS→ERP）、库存查询/同步。同步方式：REST API + Kafka事件。

### 4.2 电商平台对接

订单推送（平台→WMS，淘宝/京东/拼多多/抖音）、发货回传（WMS→平台，含快递单号）、库存同步（WMS→平台，防止超卖）、退货同步。支持多店铺管理。

### 4.3 快递商对接

电子面单获取（批量获取，面单池预取）、物流轨迹查询、运费查询、网点查询。高并发场景：批量获取面单使用Redis List队列+线程池，避免阻塞。

### 4.4 TMS/WCS/MES对接

TMS：运输计划下发、发运回传、物流轨迹。WCS：设备任务下发（输送线/分拣机/AGV）、设备状态回传、任务完成确认。MES：生产完工入库、生产领料出库。

### 4.5 AI平台对接

OCR单据识别（入库单/发票）、需求预测（AI平台返回预测结果）、自动化报表（AI生成报表）、RAG智能问答（WMS数据供AI查询）。通过Kafka事件和REST API双向集成。

### 4.6 安全机制

应用管理（每个对接系统分配AppKey/AppSecret），签名校验（请求参数+时间戳+Nonce+HMAC-SHA256签名），IP白名单，防重放（时间戳5分钟有效+Nonce去重），敏感字段加密传输。

### 4.7 异步API

Kafka事件推送（WMS业务事件推送到指定Topic，外部系统消费）、Webhook回调（外部系统提供回调URL，WMS事件触发时POST通知）、批量导入导出（大文件异步处理，完成后通知）。

### 4.8 接口版本管理

URL版本（/api/v1/、/api/v2/），向下兼容，废弃接口标记，版本变更通知对接方。

## 五、库存变化分析

API平台不直接改变库存，API调用触发的业务操作（入库/出库/调拨）导致库存变动。库存查询API返回实时库存数据。

## 六、技术实现方案

### 6.1 核心表设计

```sql
-- API应用 wms_api_app (app_id/app_key/app_secret/app_name/contact/ip_whitelist/status/created_at)
-- API权限 wms_api_permission (app_id/api_path/method/rate_limit/status)
-- 调用日志 wms_api_log (log_id/app_id/api_path/method/request_params/response_code/response_time/ip/created_at)
-- 回调配置 wms_api_callback (app_id/event_type/callback_url/secret/status)
-- 面单池 wms_express_waybill_pool (pool_id/express_code/waybill_no/status/order_id/expire_time)
```

### 6.2 网关实现

Spring Cloud Gateway：路由配置（Nacos动态路由）、全局过滤器（鉴权/签名/限流/日志/TraceId）、Resilience4j限流降级（按应用/按接口限流）、统一异常处理。

### 6.3 批量面单获取

Redis List队列缓冲面单请求→线程池消费→调用快递商API→结果写入面单池→订单关联面单。失败重试（3次），降级（切换快递商）。

## 八、常见业务问题与解决方案

| 问题 | 解决方案 |
|------|---------|
| 接口并发高 | 限流+队列缓冲+异步处理+水平扩展 |
| 外部接口不稳定 | 超时+重试+熔断+降级+备用通道 |
| 面单获取阻塞 | 面单池预取+Redis List队列+线程池 |
| 数据同步不一致 | 事件驱动+对账+补偿机制+幂等 |
| 接口安全风险 | 签名+IP白名单+防重放+加密+审计 |
| 对接周期长 | 标准化API+完整文档+在线调试+SDK |
| 接口版本混乱 | URL版本+兼容策略+废弃通知+迁移指南 |
